# Exora references and integration review

Reviewed November 25, 2026. The target is Minecraft **1.21.1**, **NeoForge 21.1.267**, and **Java 21**. This review uses checked-out Git source and resources at the linked commits. Compatibility is based on build files, mod metadata, and release evidence. The Valkron asset check described below was run separately. Load order, dedicated-server behavior, and coexistence with Exora remain to be tested.

## Reuse categories

1. **Direct reuse with permission.** Use an upstream API or released dependency under its applicable terms, or carry approved files with their notices and provenance. Verify rights per file and intended use, especially for art, sound, fonts, and dependencies inside a JAR.
2. **Adapt into Exora.** Implement a useful design idea independently using Exora's own code, data formats, and assets.
3. **Recreate as an original implementation.** Define the behavior and interfaces around Exora's progression and multiplayer needs.

## Valkron

**Source and dependencies.** Both snapshots target Minecraft 1.21.1, NeoForge 21.1.267, and Java 21, using ModDevGradle 2.0.78 and Gradle 8.9. Main has no additional runtime mod dependency. The unmerged animation branch pins `software.bernie.geckolib:geckolib-neoforge-1.21.1:4.9.3` from GeckoLib's Maven and requires GeckoLib `[4.9.3,5)` on both sides. Both snapshots declare All Rights Reserved and have no repository license granting downstream reuse. [Main tree](https://github.com/sebasjuricek/Valkron/tree/87eb536d907bcbecce4728409c7754a198220557) · [Animation tree](https://github.com/sebasjuricek/Valkron/tree/cb3caf251af8612d5d30be674852632bb6a6013e) · [Animation build](https://github.com/sebasjuricek/Valkron/blob/cb3caf251af8612d5d30be674852632bb6a6013e/build.gradle) · [Animation mod metadata](https://github.com/sebasjuricek/Valkron/blob/cb3caf251af8612d5d30be674852632bb6a6013e/src/main/resources/META-INF/neoforge.mods.toml)

**Architecture and assets.** `Valkron.java` registers items, entities, sound events, and data components. `ValkronClient` combines hand transforms, a vanilla model predicate, key input, a localized status HUD, and disconnect cleanup. `EnergyBoltRenderer` draws a layered camera-facing effect. Main has 20 item model JSON files, item and effect PNGs, 16 OGG files, `sounds.json`, and `en_us.json`. The offline generator uses Python, Pillow, NumPy, and SoundFile to produce models, textures, synthesized audio, and game data. Valkron supplies an overlay and held-item presentation. The review found no general-purpose workstation menus, machines, power system, vehicles, or research infrastructure. [Registration](https://github.com/sebasjuricek/Valkron/blob/87eb536d907bcbecce4728409c7754a198220557/src/main/java/dev/valkron/Valkron.java) · [Client HUD and input](https://github.com/sebasjuricek/Valkron/blob/87eb536d907bcbecce4728409c7754a198220557/src/main/java/dev/valkron/client/ValkronClient.java) · [Effect renderer](https://github.com/sebasjuricek/Valkron/blob/87eb536d907bcbecce4728409c7754a198220557/src/main/java/dev/valkron/client/EnergyBoltRenderer.java) · [Sound definitions](https://github.com/sebasjuricek/Valkron/blob/87eb536d907bcbecce4728409c7754a198220557/src/main/resources/assets/valkron/sounds.json) · [Asset generator](https://github.com/sebasjuricek/Valkron/blob/87eb536d907bcbecce4728409c7754a198220557/tools/generate_assets.py)

**Animation branch.** `GeoGunModel`, `GeoGunRenderer`, and `GunAnimationController` pair baked geometry, animation clips, base textures, and glow masks. The branch separates held views from neutral item rendering and distinguishes local preview cues from server-confirmed cues. Its art guide describes the asset contract, and the checked-in offline validator passed structural checks on all five fictional rigs. The repository provides exported geometry and animations. Editable Blockbench or Blender project files were absent from the reviewed tree. [Model lookup](https://github.com/sebasjuricek/Valkron/blob/cb3caf251af8612d5d30be674852632bb6a6013e/src/main/java/dev/valkron/client/GeoGunModel.java) · [Renderer](https://github.com/sebasjuricek/Valkron/blob/cb3caf251af8612d5d30be674852632bb6a6013e/src/main/java/dev/valkron/client/GeoGunRenderer.java) · [Animation controller](https://github.com/sebasjuricek/Valkron/blob/cb3caf251af8612d5d30be674852632bb6a6013e/src/main/java/dev/valkron/client/GunAnimationController.java) · [Art guide](https://github.com/sebasjuricek/Valkron/blob/cb3caf251af8612d5d30be674852632bb6a6013e/docs/weapon-art.md) · [Validator](https://github.com/sebasjuricek/Valkron/blob/cb3caf251af8612d5d30be674852632bb6a6013e/tools/validate_weapon_assets.py)

## SuperbWarfare

The `1.21` branch targets Minecraft 1.21.1, NeoForge 21.1.228 with minimum 21.1.203, and Java/Kotlin 21. The `0.8.9.2-1.21` tag uses the same platform family. ## Applied Energistics 2

**Source and dependencies.** The `1.21.1` branch targets Minecraft 1.21.1, Java 21, and NeoForge 21.1.169 or later. Default `main` targets Minecraft 26.3 and Java 25. The NeoForge 19.2.20 release is available from Maven Central both as the full mod and with the `api` classifier. The shipped mod metadata requires GuideME 21.1.1 or later, and the published POM declares GuideME 21.1.1 at runtime. The README's older installation text omits that requirement. EMI, The One Probe, and Jade are optional in the metadata. The README assigns MIT to the API, LGPLv3 to the implementation, CC BY-NC-SA 3.0 to models and textures, and CC0 to text and translations. It lists a separate CC BY 4.0 license for the Guidebook click sound. Check file-level headers because some implementation files specify LGPL-3.0-or-later. **Architecture and resources.** `MEStorage` separates simulated and committed transfer operations. `ManagedGridNode` owns attachment and NBT lifecycle. ## Incremental integration plan

Treat each step as a separate project change with its own acceptance check. The foundation build and the first industrial loop stay independent of the reviewed mods.

| Order | Scope | Ready when |
| --- | --- | --- |
| 0 | Preserve this comparison and the platform baseline. For every future import record the repository, commit, exact path, author, license or permission, attribution, and authorized edits. | The candidate has a specific use in the roadmap and documented rights. The baseline builds on Java 21. |
| 1 | Make the first original survival loop with materials, a small generator, one powered processor, and a research unlock. Carry forward HBM's legible machine states and AE2's simulated transfers as design ideas. | In a fresh world, the loop works with Exora alone. Check blocked output, save/restart, and two players using the station on a dedicated server. |
| 2 | Integrate one fictional presentation element. Start with a cleared Valkron effect or an original animated industrial tool or robot part. If complex keyframing is needed, test one NeoForge GeckoLib 4.x artifact in a disposable profile. | Resource reload, first person, third person, GUI display, and dedicated server startup all pass. If the asset is reused, all references resolve under `exora` and Valkron still loads alongside it. |
| 3 | Build the first utility vehicle and service bay around Exora research, manufacturing, charge, and maintenance. Adapt SuperbWarfare's split between visual definitions and vehicle state, and TaCZ's data reload and workstation patterns. | The server validates control and maintenance actions. Ownership and parts survive save/restart. Test two players, reconnects, chunk tracking, and invalid data reloads. |
| 4 | Add optional AE2 interoperability once a concrete logistics use case exists. Keep it behind the public API and an explicit mod-presence check. | Run Exora with and without AE2 and GuideME. Verify simulated and committed transfer outcomes, blocked outputs, and unchanged Exora save formats. |
| 5 | Add more fictional equipment and Overworld challenges once the industrial loop and presentation pipeline are proven. Add upstream coexistence profiles only when they support a real playtest or compatibility goal. | Any new dependency has a pinned version, a rights record, and a client/server compatibility check. A dependency graph and launch test confirm the selected GeckoLib and SimpleBedrockModel artifacts if the upstream mods share a profile. |

### Boundaries for all steps

- **Registries and resources.** Exora owns `exora:*`, `assets/exora/`, and `data/exora/`. Keep a dependency's namespace intact. When a cleared asset set moves, validate all model, texture, animation, sound, and localization references in the packaged JAR. Review writes into shared namespaces separately.
- **Dependencies.** Treat source pins, shipped artifacts, and the versions a modpack actually loads as separate evidence. Prefer one external animation library version per profile. Keep compatibility classes guarded and keep libraries out of the main progression contract.
- **Networking.** Give Exora payloads their own version and direction. Validate ownership and context on the server. Sync authoritative state on tracking and send bounded presentation updates to the clients that need them.
- **Persistence.** Maintain Exora-owned data components, block-entity and vehicle state, and team research data. Test save/reload and upgrades. Keep renderer caches and animation IDs independent of gameplay identity.
